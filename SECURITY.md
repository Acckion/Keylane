# Security Policy / 安全策略

## Supported versions

Keylane is actively developed. Security fixes are prioritized for the latest development line and current releases; there is no guaranteed long-term-support or historical-version backport program. A prerelease may contain known limitations. Read its release notes before use and avoid relying on it for security-critical workflows.

## Reporting a vulnerability

**Do not disclose vulnerabilities, exploit steps, credentials, or private user data in public issues, discussions, or pull requests.**

Use **Report a vulnerability** on the repository's [Security → Advisories](https://github.com/Acckion/Keylane/security/advisories) page to send a private report to the maintainers. Private vulnerability reporting is enabled. If the private form is unavailable, do not substitute a public vulnerability report; wait for the private channel to be available before sharing details.

Include in the private report:

- Affected Keylane version/build or commit and macOS version.
- The affected component, expected security boundary, and potential impact.
- Minimal reproducible steps or a proof of concept using synthetic data.
- Any relevant mitigations and whether the issue has already been disclosed elsewhere.

Remove secrets and real personal data from all evidence. Do not test against other people's accounts, devices, or services without authorization.

This community-maintained project does not promise a fixed response deadline, a bounty, or legal safe-harbor coverage. Please coordinate disclosure with maintainers so a fix or mitigation can be assessed before public details are shared.
