# Raycast 配置导入支持进度

本表是迁移范围及后续工作的依据，不把“识别到类别”算作“已迁移”。只转换当前 Keylane 可使用且格式已验证的数据；不支持的内容只报告类别、原因和数量，不另存原始 JSON、未知配置或二进制载荷。笔记按当前产品决定暂不处理。

依据：[Raycast 官方导入导出手册](https://manual.raycast.com/import-export)、用户授权只读核对的 Raycast 2.12.1.0 加密导出结构，以及仓库合成测试。真实文件未应用到用户配置；文档不包含备份密码、聊天正文、文件路径或个人记录。

## 当前实现

| 类别 | 进度 | 可迁移内容 | 未支持 / 后续工作 |
| --- | --- | --- | --- |
| 设置（settings v1） | 部分支持 | 已验证通用偏好；明确映射的内置命令及本机已发现应用的别名、普通热键与启用状态 | 尚未映射的命令、内置扩展偏好、特殊修饰键手势、主题、搜索范围与授权书签；独立权限开关不迁移 |
| Quicklinks v1 | 部分支持 | 名称、可表达的链接模板、稳定身份、去重 | Raycast 专属模板、打开方式、标签/图标与使用统计；不猜测目标应用 |
| Snippets v1 | 部分支持 | 纯文本、标题、可兼容动态模板、关键词、标签；稳定身份与重复导入 | 富文本/图片、无法解析的模板；关键词冲突清空导入项关键词并报告 |
| AI v2：聊天 | 部分支持 | 对话标题、问答文本、思考文本（每轮最多 16 KB）、更新时间与归档状态；本机历史可查看和复制 | 原模型账号、继续生成/重试、工具消息/结果、附件文件、项目/文件夹、模型参数与使用统计。仅附件的用户轮次及其回复跳过，保留边界避免误归属。历史使用明确不可用的模型引用，不能误用已有账号发送 |
| AI v2：自定义命令 | 部分支持 | 名称、可兼容提示词、稳定身份；使用 Keylane 自己的模型配置 | Raycast 模型绑定、输出策略、图标、专属模板、Agent/模式和工具配置 |
| 剪贴板 v1 | 部分支持 | 内嵌 text 类型的 text/plain 内容、标题、来源、创建/最近时间、复制次数、置顶字段（若有） | 图片、文件、HTML/RTF、多项表示组合和外部资源。不会把 blob/url 当成正文；导入不启用采集，后续遵循现有清理策略 |
| Emoji v1 | 部分支持 | 现有 Emoji 目录中匹配的使用记录和自定义关键词，关键词参与搜索 | 原精确使用时间转换为排序权重；目录外字符跳过；不改变默认肤色/动作等设置 |
| Focus categories v1 | 部分支持 | 分类名称、应用 bundle ID、网站；同名合并保留已有分类 ID | 原图标、历史专注活动、未验证会话策略；不启动会话、不启用屏蔽权限 |
| Notes v2 | 暂不处理 | 无 | 不迁入 Apple 备忘录，不保留原笔记内容 |
| Store / nodeExtensions v1 | 待支持 | 仅报告类别 | 扩展安装包、版本匹配、偏好与授权迁移；不自动下载安装或启用代码 |
| MCP servers v1 | 待支持 | 仅报告类别 | 账号、环境变量、服务启动和授权；未知数据不保存 |
| User activity / Wrapped v1 | 不迁移 | 仅报告类别 | 使用活动、统计和来源记录；Keylane 无等价迁移目标 |
| Window layouts v1 | 待验证 | 仅报告类别 | 本次样本为空，缺少非空交换格式证据。Keylane 有窗口布局功能，但不能据此假定字段兼容；需非空脱敏夹具后实现 |
| 未知类别 / 未来版本 | 不迁移 | 报告名称、版本和数量 | 不猜测字段、不存原始载荷 |

“部分支持”不表示源类别的全部记录都转换成功。分类选择显示实际转换数量，最终预览显示合并结果及跳过原因。错误版本拒绝对应类别，不影响其他已验证类别；损坏或无法认证的备份整体拒绝。

## 冲突和生效

- 用户先选择类别，再选择保留现有冲突项或覆盖来源身份相同的项目。覆盖不清空来源中缺失的现有资料。命令热键仍通过现有冲突计划检查。
- Snippet/AI/聊天使用来源身份生成稳定 ID；剪贴板按内容身份去重；专注分类也检查同名冲突。重复导入选择“保留”不会重复增加记录。
- 预览只在 0700 私有临时目录修改 Keylane 自有资料库的副本。取消不改写当前资料，临时副本清除；不打开备份引用的外部附件。
- 最终确认后保存 `raycast-pending.plist`，随后退出 Keylane。重新打开时，在控制器创建前合并已确认偏好并恢复资料库。事务只保存受影响的 Keylane 资料库前后快照，不保存不支持的 Raycast 数据。资料库快照可能包含现有私人内容，目录 0700、文件 0600，应妥善保管。
- SQLite 使用一致性备份 API，包含未检查点的 WAL 内容，不直接覆盖活动 WAL 文件。所有受影响资源在首笔写入前校验；专注分类单独核对，正常退出产生的新会话检查点在导入和撤销时均保留；中断后仅接受已知“之前/之后”状态并继续完成。不声称多个 SQLite 和偏好域之间具有单个原子提交。
- 无法完成或发现其他编辑时保留恢复记录并停止启动，避免控制器继续改写半完成状态。尚未开始写入时，即使外部数据已改变，也可在启动提示中取消此次导入并继续启动；部分完成时应重启完成后再撤销。
- 撤销仅在资料仍与导入结果一致时允许，恢复原先不存在的资料库及偏好键；后续编辑不会静默抹除。只保留最近一次成功导入的撤销依据，不是长期备份。
- 仍不迁移密码/API 密钥/令牌、系统权限、Keychain 或扩展可执行包；不调用 AI 服务或启用受权限约束的模块。

## 验证与剩余验收

- 核心合成测试：数据类型/版本、稳定身份、过滤未知内容、剪贴板编码、AI 文本/思考/附件过滤；事务重放、撤销、取消、外部编辑拒绝、SQLite/FTS 快照及旧事务互斥。
- `Keylane --verify-raycast-migration`（Debug）以临时目录验证生产解析 → 数据准备 → 启动事务 → 本机历史读取 → 重复导入 → 撤销；不创建真实 Model/Delegate，不访问真实用户域。
- 上述检查不等于安装版验收。真实导出文件的最终只读转换预览、文件选择器、分类选择、深浅色原生面板与真正重启/撤销流程，须分别记录实际验证结果。
- Keylane 原生 configuration v2 仍是有限配置导出格式，本次 Raycast 数据导入不自动扩充它；全量本机备份属于独立的导出版本升级工作，不能将本表误读为全量备份承诺。
