## 原问题

事件分类原已区分递归意图，但只有活动扫描的实时补丁使用它；正常增量路径仍会递归任何目录。普通根元数据通知还会转换为根目录完整枚举。前缀合并会把父目录下面的明确文件事件丢掉，一旦父目录改成只更新自身，就必须一起修正此规则。

## 实现

- 待办同时保留直接路径与递归路径。普通目录修改只更新目录行；没有修复待办的普通根元数据不启动扫描。
- 新建/重命名、忽略规则变化、MustScan 和目录权限/所有者变化保留递归。缺少类型标记的创建/重命名也保守检查；实际是文件时不会枚举子项。
- 当前范围内的 MustScanSubDirs 只补扫对应子树。丢事件/编号回绕、根身份与卷变化继续完整恢复；涉及配置根祖先但不在根内的 MustScan 也保守回退。
- 只有递归父目录可以覆盖子路径；浅更新父目录必须保留子文件事件。Set 合并重复路径，保持最早事件起两秒调度，不因后续事件无限推迟；保留原单运行加最新待办、8192 上限及溢出恢复。
- 删除对账新增 exact-entry 路径：目录自身更新不使其后代过期；目标消失、变为文件/符号链接或被规则排除仍清理对应子树。
- 先前不可读的修复路径遇到自身或祖先通知时，递归复核该修复子树，不允许浅更新后提前清掉修复状态。启动重试及变更排除规则也保留递归意图。
- 空结果不再提交实时补丁任务。
