# 暂存架

实现状态：第一版原生底层与界面已接入；**真实跨应用拖放尚未验收通过，不能标记为可发布或与 Dropover 完全等效**。

## 入口与交互

通过「新建暂存架」「从剪贴板创建暂存架」「选择暂存架」命令打开，或者将内容拖到菜单栏的暂存架图标。拖动内容时左右摇晃指针会在附近显示新架。摇晃使用鼠标状态轮询，不申请辅助功能、不安装全局事件 tap；灵敏度目前固定。

首次加入默认快捷键为 ⌥⇧Space、⌥⇧A、⌥⇧S。只安装一次，不替换既有绑定，也不覆盖 Keylane 中已占用的组合。系统注册冲突仍由现有快捷键管理器报告，并保留独立可用的快捷键。可在设置中的共享命令列表改绑或关闭。当前「选择暂存架」聚焦第一个打开的架，没有 Dropover 的编号选择界面。

紧凑态为正方形，复用 Launcher 的 NSGlassEffectView、连续大圆角及非激活面板，无标准红绿灯按钮。左上关闭，右上展开/收起；中央缩略图可作为拖入/拖出区域，底部文件名胶囊打开详情。详情包含多选列表、名称、固定、复制、粘贴、清空和取消加载。外观跟随 Keylane 的系统/浅色/深色选择；缩略图在后台生成。

激活架后，⌘W 关闭、⌘C 复制、⌘V 粘贴、Delete 移除选中内容（无选择时清空）、Space 打开文件 Quick Look。关闭保留最近记录，清空只移除暂存记录。固定架持续保留，最近历史最多保留 10 个未固定架；重启后可通过菜单重新打开。成功拖出默认关闭窗口，可在设置改为保持打开；取消或拒绝保持内容。

默认向目标提供系统复制/移动协商，同卷目标可能选择移动。按 Option 可复制；设置中的「默认复制到目标」限制为复制。源文件的移动由接收应用执行，Keylane 不在拖动结束回调执行移动或删除。

## 内容与数据边界

- Finder 文件和目录保留安全作用域书签，不复制进仓库或私有缓存。拖出前重新检查可读性；改名/移动后重新解析书签并更新记录。源消失时从架中移除并反馈；无权限时报告失败。
- 文本、普通链接、PNG/TIFF/JPEG/GIF/HEIC 原始图片数据可接收；链接不会自动下载或打开。图片保留原数据，内容哈希用于重复判断。文件、文本、链接各按自身标识去重，不按显示文件名去重。
- 普通粘贴与真实拖放是不同入口。NSFilePromiseReceiver 仅在原生拖放回调内调用；普通剪贴板仅读取可直接消费的文件 URL、图片、链接或文字，不能直接兑现文件承诺。
- 每次文件承诺拖入使用同一个独立批次目录，在后台接收；多接收器共用该批次目录。批次按来源顺序提交，不因回调完成先后重排。失败可部分成功，并给出错误。
- 取消、清空、关闭或模块停用撤销批次提交资格，不假设来源应用已经停止写入。迟到回调不能恢复条目；全部回调完成后清理失败/取消残留。启动时清理上次中断的私有目录。
- 外部引用永远不进入清理器；清理只扫描 Keylane 所有的 Assets/Incoming。已经拖出到外部位置的文件不会被清理器删除。复制到剪贴板后保留授权至架关闭；Quick Look 单独持有预览期间授权并随架关闭释放。
- 文字、图像、文件承诺和记录均只存本机。生成内容单项 64 MiB、每架 1000 项、记录总文件 32 MiB 上限，持久化失败回滚内存记录。目录 0700、记录和生成数据 0600。临时导出文件在后续进程启动时回收，避免拖出期间被提前清理。

不包含云上传、付费服务、监控文件夹、缺口投放、分享扩展、脚本、停靠架、编号选择器、架颜色或其他第二阶段设计。没有第三方私有代码、品牌或用户参考图素材。

## 架构

`DropShelfStore` 在 KeylaneCore 管理可恢复记录、外部引用、私有资产和事务回滚。`DropShelfController` 管理模块服务、菜单栏、窗口、摇晃及偏好。`DropShelfWindow` 承接原生面板、列表与输入输出；`DropShelfPreview` 承接紧凑面板的原生拖放。`DropShelfReceiving` 分离批次事务与 AppKit 接收器，允许可控异步测试；生产适配器仍使用 NSFilePromiseReceiver。

模块经 LauncherModuleRegistry 注册命令、设置和服务，菜单栏经现有 MenuBarRegistry 管理；新增拖入覆盖层只属于相应状态项，在隐藏/停用时移除。Quick Look 沿用 FilePreview，使用独立的 shelf owner，不抢用其他模块的预览生命周期。

官方研究来源与日期见 [设计调查](design/DROP-SHELF.md)。用户在 2026-11-17 确认相关行为与 Dropover 一致，并提供正方形液态玻璃参考。尚未达到完全一致的部分在此明确列出，不作为已完成能力。

## 验证与限制

2026-11-17 已执行：

- 203 项 Swift 测试通过（含六项暂存架存储测试）；后续微调继续以最新验证记录为准。
- 版本检查通过；18 项 ReleaseTests 通过。
- 独立应用夹具验证正方形尺寸、无标准标题栏、命名 pasteboard 四类输入、去重、源文件保留、重新加载、改名书签追踪。
- 可控异步提供方验证乱序输入顺序、失败反馈、不增加伪条目、取消后迟到回调不恢复内容、失败/取消目录无残留。这是事务测试，**不是真实 AppKit 拖放验收**。
- Mac CUA 已打开紧凑窗口，并用按钮展开内容列表，观察焦点转入列表。后续正方形约束有夹具断言；最终外观仍需重新实机目视验证。
- Finder 合成图片已选中；跨窗口拖入尝试未让架接收到内容。窗口移动尝试也未改变窗口边界，之后 CUA 状态调用超时。原因未确定，不能归因于产品已通过，也不能把该尝试写成成功。

尚未通过：Finder 拖入/拖出（移动和 Option 复制）、拖出取消、目标拒绝、实际鼠标摇晃、菜单栏拖入、Safari 图片与链接、Mail 附件、多项真实文件承诺、受保护目录权限提示、多屏/全屏、深浅色和减少透明度的最终验收。不会为了验收更改系统安全设置。

曾发现并已修复两个夹具问题：使用自己的 bundle ID 初始化 suiteName 导致 nil 强制解包；在命名 pasteboard 上直接兑现真实文件承诺触发 AppKit 异常。后者同时促成生产入口分离，普通粘贴不会调用真实文件承诺接收 API。失败记录保留，不作为通过证据。

## 独立验收方法

```sh
bash scripts/verify-drop-shelf.sh --prepare
```

脚本输出独立测试应用、合成承诺来源应用和根目录。普通不带参数运行执行合成验证并退出；`--prepare` 保留测试应用用于实机操作。通过 `open -n` 给测试应用传入脚本输出的 `CFFIXED_USER_HOME=<Root>/home` 和 `KEYLANE_SHELF_FIXTURE=<Root>`，以及 `--interactive --image-preview --dark` 或 `--light`。应用 bundle ID 使用独立测试前缀，不启动 Keylane 原有服务，不覆盖安装版本。

1. 用 Finder 打开 `<Root>/Fixtures`，拖入 `source.txt`、`fixture.png` 和合成目录，确认源仍在原处。
2. 拖出到 `<Root>/Destination`，分别验证系统默认与 Option 复制；同时检查架的最近历史及源路径。
3. 将架中内容拖到不接受的区域，取消或拒绝后确认内容仍在。改名/删除合成源，再回到架检查引用与反馈。
4. 打开测试承诺来源应用，分别拖动多个正常、失败和慢速提供方；慢速期间取消加载，等待完成后检查架及 Incoming 残留。
5. 用 Safari 打开 `<Root>/Fixtures/index.html`，拖图片、文字、链接；用 Mail 只处理自行创建的合成附件，不使用真实邮件或账户内容。
6. 验证关闭重开、固定、键盘焦点、深浅色及多个显示器。逐项记录真实动作与结果，任何未完成项继续标记待验。

当前仅为功能分支交付，必须在上述验收完成前保持草稿状态，不合并或发布。
