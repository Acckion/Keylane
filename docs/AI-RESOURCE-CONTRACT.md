## 三个不同的对象

- `AIResourceReference` 是模块命名空间内的稳定资源身份。URI 使用版本号、模块编码与来源 ID 摘要，不包含原始文件路径/数据库 ID。相同来源的内容变化不改变身份；不同模块相互隔离。URI 可编码、比较和持久化，但没有解析器或权限恢复入口。
- `AIResourceSnapshot` 描述一次不可变提取：资源引用、来源版本、正文摘要、读取时间和独立快照 ID。模块动作、聊天附件和工具读取结果复用它。正文仍保存在已有上下文/附件/结果字段，不重复存储。
- `AIResourceReader` 是仅驻留内存的模块来源解析器。它复用 `AIActionSource`，读取前后检查可用性、来源版本及取消。注册表原有激活/功能代次包装继续生效。已保存的 URI/快照不能重建 reader。

## 已确认的用户行为

加入草稿后固定当时的内容。源文件或模块记录随后变化，不自动替换，也不在发送时重新读取。用户点击附件上的“重新读取”才重新检查来源并生成新快照；保留附件位置/ID、原草稿和选区，不自动发送。失败、撤权、来源身份切换或超限时保留原快照，并显示错误。

重新读取仅支持当前草稿中仍持有运行期 reader 的来源。移除附件、取消读取、切换草稿或清空会使旧结果失效；刷新结果不能重新插入已删除附件。进程内保留草稿可保留 guarded reader；历史/导出/同步只保留快照元数据和正文，恢复后需重新选择来源，不能凭 URI 恢复权限。已发送消息保持不变。

原来的普通附件和旧聊天 JSON 不需要迁移，缺少资源元数据仍可展示和发送。OCR 图片附件、AI 生成结果等没有可验证 reader 的历史内容保持静态，不能用“重新读取”伪造权限。模块来源（含截图 OCR）和所选文本/PDF 文件使用公共 reader。

## 模块和工具边界

模块动作的预览/执行仍沿用原有发送前版本检查；快照身份不替代命令准入。日历来源按原事件 ID 读取最新已加载记录；截图按同一来源读取并核对版本；文件选择的组合身份按规范化 URL 序列生成，不能把所有选择都标成 `selected-files`。

工具的搜索引用、路径授权和分页游标仍是三套原有授权协议，不统一成跨运行 URI 权限：

- `keylane_read_clipboard`、`keylane_read_searched_file` 仍只接受当前运行内搜索返回的随机引用；文件引用仍有五分钟期限与原版本检查。文件改变后须重新搜索再确认，不自动跟随新版本。
- `keylane_read_file` 保留匹配目录和目标准备、逐次审批，`keylane_read_result` 保留原版本/私有结果快照与逐页审批，不重新扫描，也不变成“读取最新”。
- 原生文件读取及引用读取结果携带同一种宿主快照元数据。传输只发送原有 `text`，不把资源 URI/元数据转成模型可用权限；未改工具名称、参数、限额或确认循环。

目录枚举不读取正文，不生成快照，不申请权限。读取、重新读取与 OCR 均由显式选择触发。

## PR #227 P1：附加命令的 reader 生命周期（2026-11-25）

基线远端 `4ca0bf50`，同步 dev `862bf06c`，保留双方最新改动。此前初次读取完成即取消可用性订阅，附件只检查当前命令开关，因而关闭/重新开启会恢复旧 reader。

资源读取现在为传入的可用性流建立持续、单向的生命周期：第一次 false 永久撤销，内存草稿副本共享同一撤销状态。删除对应缓存 reader 并通知界面；只取消属于该生命周期的读取，不取消其他来源。完成初次读取不结束该生命周期。正文/快照及草稿不变；恢复旧草稿副本也不恢复权限，显式新选来源建立新的生命周期。

生产命令附加逻辑抽成 `AIModule.attachResourceContext`，仍由原 `attachModuleAIContext` 入口调用。隔离测试可以通过同一个宿主路由和 `snippet-ai-chat` 的注册表准入验证，而无需构造会访问用户资料的 `Model`。没有另写读取或权限通道。

修复前 Composer 在新增回归中确定性触发“disable/re-enable revived a retained attachment reader”；修复后回归通过。覆盖同一 UI 回合的关闭/重新启用、内存副本、初次/刷新读取中撤权、晚到结果、快照/草稿保留、新选择，以及其他来源读取不被误取消。完整构建和 456 项 Swift 测试、30 项脚本测试通过。

## PR #227 P1：独立聊天的全局 AI 撤权（2026-11-25）

`e3868852` 后续审查发现文件选择器 `attachFiles` 和 `AIChatContextSheet` 不经过命令的可用性流；视图只取消正在读取的任务，不能撤销已经保留的 reader。会话现在在初始化时（包括 `observesDefaultConnection: false` 的独立聊天）让公共 Composer 持续观察全局 AI 开关，第一次关闭永久撤销当前代次。重新开启只为新选择创建新代次；已接受正文、快照、未发送草稿及内存副本不丢。

文件附件在启动提取前绑定代次，上下文选择器必须由宿主提供同一 reader 预处理入口，并在 await 前绑定。追加时拒绝旧代次、已撤销或未经当前会话绑定的 reader，避免读取后才赋予新权限。恢复内存草稿保留原撤销标记并叠加目标会话代次。各代次直接持有撤权订阅，即使原 Composer 已释放，保留 reader 的草稿副本仍会收到关闭事件。关闭 AI 还取消当前提取；忽略取消的晚到上下文也因 reader 的读后检查而失败。完成读取、窗口隐藏及草稿清空都不会终止全局撤权观察。

两项 P1 的确定性回归统一放入 `picker-resource-route.swift`，随已有 Checks 的 `verify-ai-file-tools.sh` 执行。覆盖实际 `attachFiles` 回调、关闭/再开启、重复开启、旧副本、读取中撤权、新选择、来源间取消隔离和快照不丢。

`resource-global-ai-lifetime-window.swift` 链接生产对象，以隔离偏好创建真实独立 `AIConversationSession`，通过实际上下文行、Composer 重新读取按钮和绑定 `AIConfiguration.setEnabled` 的开关验证。上下文组件留在隔离窗口中，专门证明即使未依赖视图消失，读取中撤权仍拒绝晚到数据。Apple Development 签名前后核验通过，截图已视觉核对。文件入口测试直接执行选择面板的生产 `attachFiles` 回调，未自动完成系统文件面板选取；未运行完整安装版、真实设置窗口或真实提供商，没有使用用户资料。完整构建、文件工具整套集成与独立界面回归通过；受限运行的文件工具编辑断言失败，正常系统权限下同一合成测试通过。最终完整测试、精确提交和 Checks 见 PR。
