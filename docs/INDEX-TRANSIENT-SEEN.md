# 全量对账使用临时行标记

2026-11-26 · FILE-01 / BASE-11 · PR #247。

实机 cbc58dd 对三个根做全量核对时处理 283,491 条，只更新 76 条元数据，却写入约 332 MB。旧实现每轮为所有见到的路径更新持久 file_seen，即使元数据完全相同。

全量扫描改为在 SQLite 写连接的 TEMP 表记录整数行 ID。基线提交和实时补丁用同一份集合；标记参与 SQLite 事务，取消或失败回滚时与对应写入一致。临时删除触发器清除同连接被删除行的标记，防止行 ID 复用误保留。扫描结束或取消即释放集合，不从该集合恢复进度。临时表可能占用内存或由 SQLite 溢出到临时文件，不再写正式索引库的 WAL。增量扫描、检查点协议、授权、正文凭据和数据库 schema 保持原有路径。没有用未经核验的系统事件游标跳过全量核对。

隔离对照使用同一 Release 二进制、同一批 30,000 条完全不变记录、每 64 条一批、固定读快照，将持久与临时两组交替各三次。每轮保留全部条目，正式 seen 写入从 30,000 降为 0，正式 WAL 增量从 5,174,752 降为 0 字节。墙钟中位数约 0.320 → 0.288 秒，只测本地 SQLite 对账，不含真实文件遍历、较大临时表溢出、真实修改和系统回写。

完整应用构建、临时标记回滚与跨代隔离、局部 SQL 计划、macOS 真实文件事件、重启/权限恢复和活动扫描写入积压回归通过。未安装或复测实机能耗。下一步应独立量化合法全量核对的文件系统读取，并验证按卷的事件历史连续性，避免需要重新遍历所有根。
