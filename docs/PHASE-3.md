## 文件搜索技术方案

使用Apple公开MDQuery读取系统Spotlight索引，不自行递归扫描硬盘、不重建或修改系统索引。用户目录模式以用户目录URL限制查询；本机模式用kMDQueryScopeComputerIndexed。系统未索引、隐私排除和权限不可读的文件不承诺可查，不以文件系统全盘扫描绕过。

文件名输入中的引号、反斜杠与通配符均转义；同时使用带参数的NSPredicate执行本地字面值过滤，不把用户星号解释为通配符。主线程启动查询及接收通知；读取快照时disableUpdates/enableUpdates成对执行。新查询立即取消旧实例、移除观察者并更新代次，延迟启动可取消，旧回调不得覆盖新输入。界面显示最多200项并告知截断。

文档：
- https://developer.apple.com/documentation/foundation/nsmetadataquery
- https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/SpotlightQuery/Concepts/QueryingMetadata.html
- https://developer.apple.com/documentation/foundation/nsmetadataqueryindexedlocalcomputerscope
- https://developer.apple.com/documentation/quicklookui/qlpreviewpanel

## 3.1 首轮实现与验证（0.7.0）

- 已实现独立文件搜索入口、个人目录/本机范围、180ms可取消延迟、查询代次防串结果、最多200行、打开文件、Finder定位、复制路径和Quick Look面板接入。
- 15项核心测试通过，新增中文、引号、字面星号、谓词注入及空/过长输入覆盖。
- 本机真实查询发现NSMetadataQuery和MDQuery路径均对已索引测试文件返回空，但同一文件mdfind可命中；未宣称这是所有系统的API缺陷。增加系统/usr/bin/mdfind兼容查询：Process参数数组直接传递，不经过Shell；输出限1MiB、候选最多1000项；取消会终止子进程，旧代次结果丢弃。
- 实际生成的唯一测试文件由mdimport单文件导入，系统mdutil只读确认索引开启，mdls和mdfind确认已索引。最终服务命中该文件，见phase3-spotlight-evidence.txt。没有修改/重建全局索引，没有输出其他用户文件名或读取用户文档内容。
- 兼容路径显示“Spotlight兼容查询”；其结果在输入变化或重新打开时刷新，实时文件增删更新仍待验收，不能把3.1整体标记完成。
- 尚待安装版验证：查询连续切换、中文输入法、真实打开/预览/定位、文件移走、无权限及取消。后续子阶段保持未实现；便笺延期。

## 安装版补充实测

初次本机全局范围没有命中“文稿”中的测试文件，因此没有将命令行命中冒充安装版命中。补充NSOpenPanel目录选择、只读安全作用域书签、重启解析与移除范围入口后，仅选择本轮spotlight-fixtures测试目录；安装版原生Spotlight命中唯一测试文件，状态为“1项 · Spotlight”，不是兼容查询。此结果表明目录访问范围会影响查询；未宣称已确定所有空结果的原因。

动作菜单“快速查看”实际打开系统QLPreviewPanel，并展示本轮文件的固定内容“Keylane integration fixture only.”。未使用用户文档验证，不以静态代码替代Quick Look实测。打开目标编辑器、分享、更多文件类型及实时更新仍未验收。

范围可切换为已索引本机、个人目录或选择文件夹；书签失效时提示重新选择。取消系统选择面板不改变设置。测试目录书签仅供验收，收尾时移除本次配置，不改变用户其他快捷键、偏好或资料。

收尾确认：只移除本轮spotlight-fixtures书签并恢复本机范围，其他偏好不变；生成测试文件内容核对后已删除。保留不含用户文档内容的验证摘要。
