# 文件索引重启恢复（FILE-01）

2026-11-23，基于 dev `5b4378ce`（已整合 `99c7a373` 打包修复），分支 `fix/file-index-restart-recovery`。本批只实现持久索引恢复；正文索引拆分、查询合并和缓存预算留给后续批次。

## 行为与安全边界

- 索引库保存已完成写入的 FSEvents 位置，以及索引规则、授权根目录、恢复目录、自动排除目录、卷和根目录文件身份的配置签名。读取与签名计算在后台队列执行。
- 配置和根目录身份一致时，启动读取现有索引，从保存的位置回放退出期间的事件。启动阶段到达的搜索不会绕过恢复检查另起全量扫描。内置模块不再在服务恢复时无条件扫描。仅切换 Launcher 内是否显示文件结果，不改变恢复签名，也不会卡住启动；旧记录无论保存哪种显示值，仍需其余规则与授权身份完全一致。
- 全量或增量扫描开始前作废恢复位置；只有已完成各范围的写入/清理、未取消且监听成功时才保存新位置，同时保存待重试路径。中断可能留下部分索引更新，但没有可恢复游标；下次使用完整扫描恢复。文件写入和位置提交按同一串行写入队列排序，不宣称整轮扫描是单次原子事务。短 SQLite 写事务绑定扫描起止与同一连接的数据库版本；其他连接提交会阻止保存游标，持久触发器在旧版本改动行时作废现有游标。清空索引与作废游标同事务提交，维护操作在提交后执行。首次安装保护触发器时只作废旧游标，不清空文件记录。
- 没有恢复记录的旧数据库、配置/授权/目录身份变化、事件丢失或编号回绕都会补扫。暂不可读或离线路径保存到待补扫集合，清理时保留这些子树的旧记录，其他已完成区域照常删除失效记录。重启只重试未完成范围；目录身份恢复/变化时重新核对配置。监听失败时不保存可复用位置，保留原有离线条目策略。旧版首次升级需完整建立一次基线。
- 过滤掉的事件仅在没有待扫描路径、未完成分类或恢复任务时推进游标。退出/暂停/禁用会取消监听与恢复，旧回调不能修改新运行状态。历史回放不参与实时一分钟缓存风暴判断。
- 新增单行恢复表，保留用户设置键、文件数据库记录和原有全文索引；不清空用户数据库。

## 本机发现并补充修复

首次安装验证遇到 774 项读取失败；原先“一项失败就不保存游标”的保守实现导致再次启动仍会全扫，因此未将该轮安装记作通过。现改为持久化待重试路径，并以每批 512 条元数据清理已完成区域；对失败子树保留旧记录。不存在的目录项与断链/暂时不可读路径分别处理，避免为了跳过扫描误删除旧记录。本机首次基线约 90 秒，后续结果另录。
