# 0.10.2 自动采集失败修复

## 根因

安装版的采集开关已启用，定时器运行、系统允许读取，并已观察到复制变化，但保存失败。只读检查本机数据库结构发现：早期开发版的 `clip_snapshots` 表只有 `clip_id/payload`，数据库版本号却同样是2；后续 `CREATE TABLE IF NOT EXISTS` 不会补上 `search_text`，导致携带快照的新记录写入时事务回滚。原有新建数据库测试无法覆盖这种升级状态。

## 修复

升级为结构版本3。版本1和2升级前使用SQLite备份接口备份数据库及本组件拥有的图片；在事务内检查真实字段，缺少时添加 `search_text`，然后更新版本并提交。不清空原历史、快照和置顶。不读取旧历史正文做诊断。备份列表及清理规则同时兼容v1和v2备份。

监听继续使用系统changeCount和250ms定时检查，与本地参考的SuperCMD v1轮询方式一致；本轮没有重新逆向Raycast。保留可选本地健康诊断，通过环境变量 `KEYLANE_CLIPBOARD_DIAGNOSTICS=1` 开启，仅记录计数、状态和授权枚举，不记录剪贴板内容，正常启动不开启。

## 验证

新增与本机相同的早期v2结构回归用例：修复前失败；修复后保留旧快照与置顶、完成备份、可保存新记录、再次启动不重复迁移。32项测试通过。

独立命名剪贴板测试新增真正的定时监听：不手动调用poll，自动采集连续两条文字和一张图片。与富文本、HTML、多项目、OCR、清理等既有验证一同运行。该验证不会接触用户当前剪贴板。

安装版迁移及真实新复制内容仍须分别核对，不能把测试通过等同于全部实机验收。

## 安装版核对

已安装0.10.2（build24），签名通过且安装二进制与ZIP一致。本机升级后结构版本3、search_text存在、quick_check返回ok，已生成一份完整v2备份。安装版健康计数观察到1次成功自动采集（capturedChanges=1，outcome=captured）；没有读取该记录正文或输出用户内容。诊断后以关闭诊断的正常模式重启，完整UI仍由用户确认。
