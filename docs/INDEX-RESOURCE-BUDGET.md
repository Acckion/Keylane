## 索引调度

目录遍历和文件属性读取从 SQLite 写入队列移到单个 utility 扫描队列。目录使用不递归的流式枚举，每次最多保留 64 项 URL/属性，纯记录最多合并 256 项提交；数据库队列只执行短批次事务。主目录的 Downloads/Desktop/Documents 优先顺序保留，无须保存整份目录列表。

慢基线扫描期间，已分类的文件事件使用独立、受限的元数据补丁队列。新增/修改/删除、重命名以及新建目录的子项均可先进入索引；正文提取也不再等待整轮扫描结束。补丁沿用活动扫描 epoch，写入队列上的更新集和删除墓碑阻止旧快照覆盖新数据或在清理时误删新项目。文件动作的立即删除也进入墓碑保护。

每个扫描/补丁队列至多一个运行任务和一个最新待办，实时待办和更新日志分别限制 8192 路径。递归限于创建、重命名、必须补扫及忽略规则变化的目录，普通目录属性事件不会在实时路径中重新遍历整棵树。超额路径及迟到事件保留正常完整对账；恢复点只在对账完成后提交，不提前越过未处理事件。暂停、停用、配置变化撤销旧代次；关闭释放待办和日志。单次原生文件系统调用仍不能硬中断。

范围外的挂载/卸载或根变化不触发无关全量重扫；影响已配置根或其祖先的变化仍重扫。丢事件、内核丢失和事件编号回绕无论路径均保留保守恢复。已知目标可以及时补丁，但不会取消恢复未知变化所需的重扫。

## 公共资源缓存

`CostBoundedCache` 提供锁保护的 O(1) LRU、严格的条目数/计费容量上限、超限拒收和锁外析构。`ResourceCache` 统一九类已有缓存：模块图标、工作区图标、剪贴板缩略图、截图缩略图、暂存架、主题示例、OCR 文本、链接预览和站点图标。同一类别的多个实例共享预算，不因重建工作器或多窗口而翻倍。前台计费上限合计 35 MiB，完全后台仅为模块图标保留最多 256 KiB。后台完成的旧请求不能重新填满已停用缓存。

图像按已解码像素或显示资源估计计费，OCR 按 UTF-8/UTF-16 较大值计费；不把计费容量说成整个进程的物理内存。可见视图的图片、系统绘制缓冲、原生 API 工作集和目录待办等需要另外测量。可见图片不因缓存逐出失效，截图行离开时释放自己的缩略图引用。原生模块图标保留既有裁剪与 2x 分辨率，改为确定大小的位图，避免绘制闭包继续持有原始大图。

设置和启动器显示时恢复前台预算；内容窗口完全不可见后沿用三秒空闲回收。窗口可见性也覆盖独立内容窗口，排除菜单栏按钮等非内容窗口。内存压力事件收紧预算，恢复正常后按当前窗口状态恢复；没有新增轮询定时器。数据库、索引、剪贴板记录、收藏、别名和热键均保留。

## 验证与交付边界

- Core 覆盖 LRU/计费上限、超大条目、容量溢出、借出的图片不失效、锁外析构、后台迟到工作和并发写入。
- 原生资源验证使用真实临时位图，填满九类保留缓存，验证前台计费 35 MiB、后台 256 KiB、后台迟到写入不回填，以及重新进入前台可复用。
- 动态索引集成用真实临时文件和 FSEvents，注入阻塞门停住旧快照：数据库不被长事务锁住，新增/修改的名称和正文、嵌套目录、重命名和删除仍及时可用，恢复基线后保持正确。另用注入旗标核对无关挂载、相关根变化和全局丢事件的恢复范围。阻塞门和注入旗标不当作真实耗时或实机能耗证据。
- CPU 对照使用相同的 3000 文件宽目录、300 个目录各 10 文件、相同 Release 编译条件；分别记录完整扫描 CPU 和 wall time，避免把延后工作当成省掉工作。
- 实际安装使用本机 Apple Development 证书，核对安装前后指定签名要求、二进制及运行进程。真实复验只使用自建文件，不读取私人正文或剪贴板历史。

最终测量、安装身份、60% 后台 / 40% 前台采样和云端 Checks 记录在本批 PR。短时缓存试验及单个物理内存快照不能证明长期平均低于 100 MB；发现不同构建、进程变化或用户数据变化时分开记录，不混用结果。

## 同数据完整扫描 CPU 对照

两个原生控制器均使用 Release `-O`，不打开窗口、不启用正文、不启动事件监听；显式启动索引，计入新 SQLite 库初始化与元数据扫描。同组临时文件交替五轮，最终中位数如下：

| 数据 | 前序 CPU | 本批 CPU | 前序 wall | 本批 wall |
| --- | --- | --- | --- | --- |
| 宽目录 3000 文件 | 0.2937 s | 0.2779 s | 0.3067 s | 0.2882 s |
| 300 目录、各 10 文件 | 0.4375 s | 0.4567 s | 0.4992 s | 0.4951 s |

宽目录 CPU 约减少 5.4%；多层目录 CPU 约增加 4.4%（每组约 0.019 秒）。不宣称所有工作负载 CPU 均下降。早期每 64 项提交的宽目录样本曾增加约 14%，改为最多 256 项纯记录合并提交后再做上述最终对照；文件属性仍分 64 项读取，不在事务内读取。此局部对照不代表全应用能耗或平均内存验收。
