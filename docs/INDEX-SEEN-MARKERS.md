# 独立扫描标记（第二批）

FILE-01 / BASE-11，承接第一批 PR #248。独立分支 `fix/index-seen-markers`，待合并；尚未安装。

## 存储与迁移

新增 `file_seen(path PRIMARY KEY, epoch)`，不存正文或目录展开结果。已有 `files.epoch` 保留为正文模式/版本兼容字段，不再作为扫描存在性标记。扫描无变化文件只更新紧凑表，不 UPDATE 正文行、不触发 FTS；实际内容、归属或卷元数据变化才更新相应记录。相同代次标记也跳过写入。

数据库 user_version 从 1 升到 2。在一个即时事务内建立标记表、从旧行初始化标记、安装删除触发器并升级版本；失败全部回滚，不清库，不修改正文/FTS/队列/恢复点。迁移在现有索引工作队列执行；SQL INSERT SELECT 流式执行，无全量 Swift 数组。等待事务锁后再次检查版本，支持多个连接同时打开。首次迁移需要扫描旧行并新增标记存储，其一次性读写不得混为后续日常成本。

路径作为稳定键，不依赖 VACUUM 可变的隐式 rowid。删除文件时同事务触发删除标记。已有主/子目录删除对账和不可读路径保护读取新表，保留根归属与路径边界检查。正文回写只更新正文，不能把标记恢复到旧代次。

`put` 将实际行更新与标记更新放在 SAVEPOINT 中，可嵌套原有事务；外层回滚同时恢复标记和计数。归属/卷变更及标记同样原子提交。计数新增 seenWrites，避免把扫描标记写入误称正文写入。

## 回退边界

升级后旧版本（schema 1）会拒绝 schema 2，不允许两种对账规则混写。这不是可直接降级的格式。实机安装前应在应用停止或 SQLite backup 一致快照条件下保留旧索引备份；若需要旧版，应先停止新版并恢复该完整快照，不能只改 user_version、删表、覆盖活动 WAL 或清空用户资料。本轮不操作真实索引，不自动安装或执行降级。

## 验证

新增覆盖：旧行/正文/恢复点迁移、新代次完全不 UPDATE files（审计触发器核对）、正文晚到不能覆盖新标记、删除对账、VACUUM 稳定性、外层事务取消，以及注入迁移中途失败后的整事务回滚与重新打开。

474 项 Core 测试通过；真实 FSEvents 实时更新 5 项、重启恢复（含不可读目录保留、权限恢复与丢事件）及正文生命周期 5 项通过。旧有子树/多根归属/卷/开关/过期 token 测试保留。相关集成只用自建临时文件，不访问用户正文或剪贴板历史。

基准 `Tests/Integration/file-seen-benchmark.swift` 使用相同 Release 条件、200 条约 15 KB 正文、同一 metadata stage API，对比第一批与第二批无变化扫描的新代次事务 WAL。每轮创建全新合成数据库，先截断 WAL，再记录事务写入；验证对账仍保留全部记录。该局部 WAL 指标不等于物理磁盘总写入或 12 小时能耗。长期安装版读写及平均内存低于 100 MB 尚未验收；反复扫描触发收敛及正文重试退避仍属后续批次。

最终五轮交替 Release 对照：200 条无变化记录的新扫描代次，事务 WAL 中位数从 3,324,872 字节降至 8,272 字节（约 -99.75%）；事务墙钟中位数 7.39 ms→3.25 ms。两版本均验证删除对账保留全部 200 条记录。初次 after 编译与源码收尾重叠而失效，已丢弃并使用冻结源码重新编译后执行最终五轮；不混用失效结果。此基准不含一次性旧库迁移或首次文件扫描成本。
