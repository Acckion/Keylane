# AI-13-c：文件修改、移动、废纸篓与恢复

本批按用户确认扩大范围：不仅生成编辑副本，还支持直接编辑原件、移动和废纸篓操作。从 dev `37dac2e` 的独立 `feat/ai-file-mutations` 工作树开发，随后整合 dev `01cee5a`（#228 Office/OCR/正则及 #230 听写已合入）。本批 PR 只包含文件操作增量，#226/#227 分支不修改。

## 公共入口

新增 `keylane_copy_file`、`keylane_edit_file`、`keylane_replace_file`、`keylane_move_file`、`keylane_trash_file`、`keylane_restore_file`、`keylane_file_recovery`。AI Chat、Quick AI 和各提供方继续使用同一个声明、prepare/确认/execute 和过程界面。旧 `keylane_write_file` 仍仅不覆盖创建，不把旧 mode=replace 调用悄悄升级。

- Copy：复制普通文件至空目标；Move 同时承担移动与重命名，目标冲突拒绝。
- Edit：按非空原文、替换文字和预期匹配次数做精确替换，不使用正则；Replace 是单独的整篇文本替换入口。
- Trash：仅支持与本机主目录同卷的文件，调用系统废纸篓 API，不永久删除；恢复只处理本工具记录的对象，不扫描或接管 Finder 中其他历史项目。Trash 成功通过已持有的原文件句柄核对，不以能枚举整个废纸篓为前提；后续恢复仍受系统对该位置的访问权限约束，不隐式申请 Full Disk Access。
- Restore：默认恢复到原授权根的空名称。直接恢复被编辑的原件，必须显式选择 `replace_edited_file`、提供当前 revision，再次确认；被替换的当前版本也保留为新的恢复项。

本批写入限于授权根内一级普通文件。需要子目录时先单独授权该父目录；不递归目录、不处理符号/多硬链接或未下载占位文件。复制最多 64 MiB；编辑只处理纯文本，不直接写回 PDF/Office/RTF 等容器，即使其字节可按 UTF-8 解码；原件和结果最多 1 MiB UTF-8；工具文字参数仍受原来的 16 KiB 输入额度限制，单项替换/整体新文本最多 12000 UTF-8 字节。跨卷克隆/移动与不支持的原子系统调用拒绝，不回退为复制后删除。

## 与前批安全契约的区别

准备阶段复用 `AIFileToolService.Prepared` 的根、文件、父链及 revision；不读正文或产生修改。源文件操作必须提供当前 `file_info` 的 revision，确认期间已发生的替换、内容变化、撤权会使旧计划失效。目标和接收方按原确认流程显示，模型仍只拿根句柄与相对名称。

**新增修改不是原子的“revision 相等才提交”接口。** 原生文件协调只协调参与的文件呈现器，不能锁住所有外部程序。准备和提交前检查也不能冻结其他进程。路径式移动/废纸篓以及原子交换的最后窗口仍可能遇到外部替换；提交后发现变化时可能已产生效果，明确返回“结果无法确认”，保留记录，勿自动重试或按路径回滚。不能宣称失败意味着没改动，或用原子 rename 冒充版本条件覆盖。[Apple 文件协调说明](https://developer.apple.com/documentation/foundation/nsfilecoordinator)

- 编辑先在私有区克隆并构造新版本，保留核实过的编辑前快照，再使用同卷 SWAP 原子交换；不在原件上逐段写入。
- 交换留下的旧 inode 保留，并额外克隆固定快照，避免其他程序继续持有旧描述符写入时连带改变恢复版本。
- 意外被换入的其他对象保留用于人工核查，但不把它转为可向 AI 导出的恢复能力；恢复仅提供已核实的编辑前备份。
- 复制/移动的新目标使用 EXCL 语义；不覆盖竞争者。源身份、目录和每个阶段再次核查。撤权与小提交继续共用原有 lease gate，撤权不回滚已经完成的系统调用。
- 所有协调和 IO 在 Core actor 执行，不在设置/聊天主线程扫描。文件系统和非合作进程仍可能导致等待；本批不是进程级硬隔离或任意文件系统的事务实现。

## 私有恢复区

恢复日志和快照保存在应用专属 `.keylane-ai-recovery` 目录，逐组件无符号链接打开，目录要求本用户所有且其他用户不可访问。日志先落盘，状态区分 prepared、completed、unconfirmed、not_committed、restored；不自动丢弃旧版或删除不确定结果。

恢复 ID 是持久的操作引用，**不是授权**，也不是 #217 的请求内搜索引用或 #224 的续读游标。每次恢复都要求当前目录仍被授权、根对象身份相符、备份/废纸篓对象版本有效、再次确认接收方和目标。日志中的绝对位置只保存在本机，不发送给模型。恢复目录不能通过普通文件 Read/Glob/Grep 或文件搜索引用读取，以免旁路恢复确认。

上限为 64 个待恢复操作、256 条日志和 256 MiB 私有备份；不自动淘汰。满额停止积累新备份，但仍可将已有备份恢复到空目标。编辑版恢复引用在每次执行前重新核对记录；先前已恢复的记录不能被其他提前准备的请求再次消费。当前未提供恢复区自动清理或设置管理界面，长期管理待后续完善。目录被外部移动、原授权路径由新对象取代、日志损坏、恢复对象被替换时拒绝，不擅自把旧授权迁移到新位置。

系统调用和日志之间仍存在中断窗口。例如系统 Trash 成功后进程立刻退出，可能只有 prepared 日志而没有完整返回位置；文件仍可能在系统废纸篓，需人工核对。日志不是全系统崩溃一致性保证，不自动重放待定操作。

## 验证边界

测试使用合成目录、可注入的系统调用竞态和专属模拟废纸篓，覆盖复制/编辑/替换/移动/恢复、确认、目标冲突、撤权、备份篡改及重启加载。不会操作用户文件或真实系统废纸篓，不调用真实模型，不安装、合并或发布。原生 Trash/Finder 行为、真实提供方、外部卷与安装版验收另行记录；不能以模拟废纸篓测试冒充这些验收。
