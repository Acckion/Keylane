## 实现

- 文件名/正文普通搜索的文本、正文范围、独立页面标记和路径展示标记全部相同时，重复调用复用当前请求；索引事件、正文回写和显式刷新仍能触发新查询。空查询最近记录和路径浏览保留原刷新行为。
- `LatestWorkQueue` 在现有串行队列上最多保留一个运行请求和一个待执行请求。新输入、授权/配置变化及关闭会撤销旧请求；同一查询的数据刷新允许运行请求完成，只替换待执行请求，避免更新频繁时一直没有可用结果。每个请求结束后重新排到队尾，让读取连接关闭、缓存释放及经批准的 AI 文件查询有机会执行。没有新增定时器或常驻结果缓存。
- SQLite 查询、目录遍历、Spotlight 评分和文件合并在可取消边界检查撤销状态，发布前再次核对。取消不能硬中断单次原生文件系统调用。删除操作立即撤销已经开始的合并，防止旧结果把删除项加回列表。
- 本地与 Spotlight 各自已经按相同规则排序；合并改为双路有序取前 200 项。保留本地记录优先去重、离线记录、正文匹配标记、忽略规则、授权与可见行顺序。只有有机会进入可见范围的系统结果才读取文件属性，低排名或已被本地记录覆盖的系统结果跳过检查。
- 根搜索的模块定向刷新保留其他候选仍在使用的名称预处理结果；下一次改变查询时不必重新准备全部名称。缓存仍限制在当前候选目录，不保留历史目录；评分、排序、收藏、别名和使用频次策略不变。
- 路径文字解析显式提供目录提示，避免 URL 默认初始化在主线程探测路径；真实类型、访问范围和忽略规则仍在后台检查。

## 验证边界

- Core 覆盖 5000 请求积压只保留最后一个、同查询刷新不使当前结果饥饿、共享队列公平性、取消后重用及捕获资源在锁外释放。排序回归覆盖 20 组有重复项和筛选的混合候选，逐项比对旧算法结果和分数；过期 Spotlight 评分会提前退出。
- 原生控制器隔离测试使用真实临时文件/SQLite，加阻塞门验证调度：100 次数据刷新只执行当前和最后待办两个请求，当前结果可在最后刷新完成前发布；1000 次相同公开搜索调用不增加 SQL；新输入及禁用阻止旧结果发布。人工阻塞用于确定执行顺序，不作为耗时提升证据。
- 根搜索集成使用 2000 个应用和一个文件命令：模块刷新仍只重算一个命令、复用 2000 个分数，下一次改变查询新增名称准备数为零，并与完整重新评分结果核对。
- 性能对照只使用本轮生成的文件；不读取用户正文或剪贴板，不重置实际索引。合并 CPU 是 Release 算法局部测量，不能代替长期能耗、滚动帧率或 60% 后台 / 40% 前台平均内存测量。

465 项 Core 测试、30 项发布脚本检查、根搜索模块、快捷链接、原有文件、重启恢复、正文队列及新增调度集成通过。快捷链接独立验证脚本补齐了架构更新后漏列的 AI 来源与工具运行类型；产品行为不变。新增调度集成进入既有无密钥 Checks。

性能数值、最终安装二进制身份和云端 Checks 以本批 PR 的最终验证记录为准，区分隔离测试和实机检查。本批不宣称长期能耗或平均内存低于 100 MB 已达标；资源缓存预算留到下一批。
