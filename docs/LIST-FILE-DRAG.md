维护：2026-11-25，功能分支 `feat/list-file-drag`，待合并。跟踪 FILE-02-a，涉及 FILE-02、CLIP-01、EXTRA-02。

主搜索和文件搜索中的文件、文件夹，剪贴板的文件组与图片缓存文件，以及下载列表均通过共用 `ResultListButton` 接入原生拖拽。拖出后只提供复制操作，不移动源文件；剪贴板文件组一起拖出。纯文字记录保持原行为。

普通点击沿用原动作。移动至少 5 点才准备拖拽，开始拖动后不再触发点击。异步准备在松手、行替换或销毁后失效；原生拖拽开始后独立持有文件授权和源视图，直至系统会话结束。拖拽不读文件正文，不申请额外目录授权；文件失效或不可读时不启动会话。

### 最短手测准备

`bash scripts/verify-result-file-drag.sh --prepare-ui` 运行离屏检查后保留临时合成文件和 `Open-Drag-Test.command`，**不会打开窗口**。只有前台操作获授权后，手动运行输出的命令文件。它复用生产 `ResultListButton` 和原生拖拽组件；仅主题/布局常量为隔离替身，不启动应用模型，不访问正式配置。程序未签名，不需要私钥。它不是完整 Launcher，也不能替代三模块的安装版验收。

1. 点“打开合成文件接收目录”，将三个测试行分别拖到 Finder；核对单文件、文件组、目录副本及源文件仍存在。仅测试这个临时目录，发生重名时取消，不替换现有项目。
2. 再拖一行，分别按 Escape、放到不接收文件的区域；确认不新增文件，点击计数不因拖动增加。拒收目标是否确实拒收需要现场确认。
3. 勾选拖动后隐藏窗口，再拖到上述接收目录；测试窗口 0.5 秒后隐藏、5 秒后只恢复显示，核对复制完成。此项验证共用组件被移除/隐藏时的行为，实际 Launcher 的隐藏代理与焦点流程仍另行验收。
