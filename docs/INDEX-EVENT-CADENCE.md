# Library 文件事件的扫描反馈

2026-11-25 · FILE-01 / BASE-11 · PR #247

实机在同一 b5e98b1 进程中重现，授权范围包括整个用户 Library。此前 50 轮扫描的日志只包含计数，并不保留历史路径，无法逐轮反查。75 秒的并行 FSEvents 旁路只记录类别、标志和匿名编号。该时段应用完成 17 轮增量扫描，处理 124 条记录，累计扫描墙钟约 0.353 秒。旁路通过现有范围及主要忽略条件的候选事件共 221 条：偏好文件 78 条、Biome 61 条、Keylane 自己的偏好 plist 19 条、其他系统分析服务 5 条，其余为容器、工作区和其他来源。候选是事件通知，不等于 SQLite 更新次数或同数量的独立文件。

原实现在每轮扫描结束时把含耗时的统计写回 UserDefaults，并无条件保存自动排除表；自动排除计数变化也触发存盘。用户显式选中 Library 后，偏好文件本身被监听，写回可以再触发一轮扫描。现在统计直接用索引里的数据，自动排除只在规则变化时存盘。只更新事件位置的空闲检查点写入合并为至多每 30 秒一次；扫描完成的检查点仍立即保存。

仅在宽范围内收到 Biome、Preferences、IntelligencePlatform、DuetExpertCenter 的普通变更时，按首个事件设定 30 秒截止时间，后续通知不能延长。普通文件、用户显式选中的更窄目录、规则修改、待修复项恢复及事件丢失保留优先级。待处理目标不排除、不丢弃，仍由同一批索引并在完成时提交检查点。没有改变授权、数据库结构或已有文件条目。

## 目录属性通知的扫描范围

2026-11-25 · FILE-01 / BASE-11。安装版 bf5d10b 的 75 秒后台样本完成 8 轮增量扫描，其中一轮紧随 iCloud 目录属性通知，处理 6,668 条记录、只写入 5 条变化的元数据。日志和匿名旁路样本可对齐时间，不能回推出个人目录或证明全部磁盘读写都来自该轮。

FSEvents 的 inode 属性标志不再单独触发递归。普通目录只更新自身，保留已索引的子项；可读的范围根目录没有索引行，直接跳过。浅更新发现目录权限拒绝时只记录待修复路径并保留旧子项，后续权限通知可唤醒指定的待修复子树。目录新建、移动、所有者改变、忽略规则改变和事件丢失仍使用原递归／基线恢复路径。测试用隔离目录确认 inode 通知的处理范围、真实 chmod 能单独发现权限丢失和恢复，以及旧记录在不可读期间不丢失。
