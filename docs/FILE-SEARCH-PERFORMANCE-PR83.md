# 文件搜索目录浏览性能复测

对照为同步 `dev` 后的 PR #83 `024ca56`，优化代码为 `c2eb72e`，同期集成基线为 `ba5598f`。旧 head `cbf4b82` 的预查也复现了大目录延迟。两组在同一台 Apple Silicon Mac 依次运行隔离的 Release 构建，使用同一合成目录和独立空索引。大目录包含 12,000 个文件，输出上限为 200。另用小目录、60 条最近记录和指向授权外文件的符号链接验证功能。

开发基线 `ba5598f` 的关键词初次查询为 79.66 ms，20 次重复为 128.11 ms，首次建索引为 1.30 秒。这些是独立参考样本，开发基线没有最近文件、直接目录浏览及排序等入口。

按名称浏览时，原实现会在截断到 200 项前为每个候选执行路径解析、授权和忽略检查并读取文件元数据。优化在配置路径都与规范化解析路径一致时先排列目录项名称，再按顺序调用原有验证与元数据读取，直到取得 200 项。忽略、排除、可读性、符号链接和内容类型规则仍由同一检查实现。路径别名和日期排序走原有完整扫描。最终版本重复按修改时间排序的中位耗时约 2.4 秒，单次切换到日期排序在优化组记录到 4.26 秒，日期路径仍是瓶颈。推迟日期排序的类型读取原型只把重复创建时间排序改善约 8%，因此没有纳入提交。

## 测量边界

- 窗口数据就绪指结果已发布且搜索状态结束。布局使用真实 `NSHostingView`，等待第一条目标结果的出现标记后完成 AppKit 布局。屏幕呈现、Quick Look 内容完成、真实系统授权和外部打开未计时。首次样本是进程首次进入该路径，系统文件缓存未清理。
- CPU 使用进程时间。内存为 macOS physical footprint，隐藏区间约 5 秒、每秒采样。两组都观察到短时内存波动，包括在停用后仍保留的框架分配。数据不支持降低整应用空闲内存的结论。
- 连续切换、取消和停用断言没有过期结果发布。集成测试另覆盖 FSEvents、授权外符号链接、忽略与排除、路径和日期排序、文件类型、暂停时读取旧索引以及重新启用后补索引。新增回归验证跳过不可显示项后仍填满 200 项，并在浏览中取消。
