# 图片、窗口与区域视觉上下文

初始基线：dev `37dac2e`；交付前整合 dev `036cfd7`（#230 听写修复）。[PR #229](https://github.com/Acckion/Keylane/pull/229) 为待合并功能；没有安装、调用真实模型或采集真实应用内容。关联功能总表 AI-05 / AI-05-a。

## 入口与行为

Quick AI 与 AI Chat 共用 `AIConversationComposerView` 的加号 / `@` 菜单：

- **附加图像（视觉模型）**：系统文件选择器显式选择图像。缩放、去除来源元数据后加入草稿，可以点附件预览。发送时包含真实图像块。
- **窗口或区域（视觉模型）**：列出可共享窗口，用户选择后读取并预览；可以拖动框选窗口内区域。只向草稿加入该窗口/区域的图像、完全位于该范围内的辅助功能文字，以及区域 OCR。取消不加附件。
- **窗口文字（辅助功能）**：使用进入选择器时记录的上一个应用，只列该应用的窗口。用户选择窗口后读取、预览其可访问文字；不截屏，也不请求屏幕录制权限。
- 原有 **从图片文件提取文字** 保留，适用于用户明确只需 OCR 的场景。不会把视觉请求悄悄转换成 OCR 请求。

所有入口都保留已有草稿、选区和附件，不自动发送；草稿重置、关闭 AI、关闭选择器或重新选择来源会取消旧工作；公共 Composer 的上下文代次还使原生文件选择器在关闭/重新开启 AI 后无法恢复旧回调，并拒绝晚到结果。新附件为固定采集快照，有来源与时间标记，不自动跟随窗口变化。

## 边界与复用

`AIConversationAttachment` 增加可选 `AIImageInput` 和 `AIVisualSource`；旧附件/旧 files 编码保持兼容。Turn、SQLite 历史、复制会话和重新提交沿用公共会话，没有第二套消息存储。来源元数据不作为权限或模型参数发送。

`AIImageInput` 是有界的 JPEG/PNG 栅格数据。`AIMessage` 统一编码 OpenAI Chat Completions 的 `image_url` 与 Anthropic 的 base64 image block，普通请求与带工具的请求使用同一编码，工具续接与后续对话保留图像。图像 API 合约参考 [OpenAI 公开文档](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)、[Anthropic 公开文档](https://platform.claude.com/docs/en/build-with-claude/vision)。

仅已声明 `supportsImages == true` 的 HTTP 模型可发送图像。未知、明确不支持及目前只实现文本传输的订阅 CLI 都在读取凭据或启动请求前拒绝，不做静默降级。用户可以选择支持视觉的模型，或移除图像并明确走 OCR/辅助功能文字入口。没有用模型名称推断能力。

系统采集由宿主 `AIVisualContextSheet` 处理，与原生文件选择器处于同一层；不授予模型自行截屏/遍历辅助功能树的工具。`AIWindowVisualCapture` 使用 [ScreenCaptureKit 单窗口截图](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage%28contentfilter%3Aconfiguration%3Acompletionhandler%3A%29)，不启动持续捕获流。窗口目录不读正文；选定窗口后才采集。AX 读取位于后台，绑定 PID、标题、窗口矩形和原 AX 窗口对象。窗口变化后拒绝旧读取；跳过隐藏/受保护/密码控件，不读取 WebArea/Group 的不透明整段值。文字保留标题、正文、按钮、链接等角色标记；框选时按节点矩形过滤，部分跨出范围的整个节点文字舍弃，由区域 OCR 补充。

这不是稳定资源 URI 或持久化 reader：在途 #227 的 `AIResourceSnapshot` 与这里的可选图像数据/采集描述可以组合，实际整合需在其合并后验证。没有修改 #226/#227 或复制其模块选择、重新读取架构。

## 额度、权限与性能

- 文件导入仅普通、非符号链接图像，源文件最多 20 MB / 4000 万像素；通过描述符读取并核对前后版本。动图只取第一帧；输出重新绘制、编码成 JPEG，移除原 GPS/EXIF 私密字段，最长边 2048，每张最多 768 KiB。
- 每条消息仍最多 5 个附件；单次请求含历史最多 5 张图像、合计 3 MiB 图像数据。文字额度保留原 32000 / 历史 64000 字节；图像请求体上限 6 MiB，纯文字请求仍为 1 MiB。
- 历史按原来“最近完整轮次”的策略截取，并同时核对图像预算；不会只保留一个轮次的文字、暗中丢掉其图像。原轮次与本机历史不被改写。
- 采集窗口最长边 2048，不把原始全分辨率屏幕缓存在会话。聊天列表只解码 96 像素缩略图；打开预览才加载完整图，关闭后释放。
- AX 树最多访问 400 节点、700 ms 循环预算，远程调用设置短超时；文字最多 20000 字节。AX/OCR 合并去重后最多 24000 字节，不在主线程 OCR，也不向根搜索转发逐片段更新。
- AX 与屏幕录制分开检查，缺少权限时由用户点按钮进入系统授权。采集完成和发送前重查；带工具的每次后续 POST 再检查。历史窗口文字/图像仍受相应权限检查，图像文件本地快照不依赖屏幕录制权限。没有常驻权限轮询/截屏服务。
