# AI 基础文件工具

## 调查边界与实现顺序

调查日期：2026-11-20。只参考公开手册与用户提供的界面截图，不使用 Raycast 私有实现。公开手册没有列出所有内部文件工具的完整名称和参数，因此不能把下面的 Keylane 工具名当作 Raycast 的官方接口清单。

| 证据 | 可以确认的能力 | 对 Keylane 的含义 |
| --- | --- | --- |
| [Raycast Projects](https://manual.raycast.com/ai/projects) | 项目工作目录支持读取、修改文件；本地目录不会自动上传整个项目 | 项目目录作为本次会话默认根目录，实际读取结果才进入模型上下文 |
| [File Search](https://manual.raycast.com/file-search) | 文件搜索范围、忽略规则和内容设置；AI 使用文件搜索与 Finder 能力 | 索引搜索与按路径读文件分开，已知路径不能依赖索引命中 |
| [AI Extensions](https://manual.raycast.com/ai/ai-extensions) | 工具可来自内置能力、扩展与 MCP，执行受权限控制 | 基础文件能力由宿主提供，业务工具仍由对应模块登记，共用执行与确认层 |
| [AI Chat](https://manual.raycast.com/ai/ai-chat) | 附件、工具和大结果处理 | 用户主动附加文件与模型主动读文件是两个入口，不能混同授权 |
| [开发者工具 API](https://developers.raycast.com/api-reference/tool) | 扩展可以声明工具及参数 | 统一声明契约，不在聊天窗口或提供商适配器里实现文件操作 |
| 用户提供的下载目录执行截图 | `Search Indexed Files`、`Search Tools`、`Glob`、`Read`；`Read` 参数为目录路径 | 这些名称与目录读取行为有直接界面证据；截图没有证明其他内部工具的精确参数 |

按依赖分批：

1. **本批已实现**：工具元数据发现、授权根目录、目录/文本读取、元数据、Glob、文字搜索、仅不覆盖创建文本与目录。覆盖和编辑在许可收紧后停用。
2. **后续**：PDF/其他文档提取、大结果文件与更好的分页、文件搜索索引工具与基础工具的检索协同。
3. **后续单独评审**：条件覆盖/编辑、复制、移动、重命名、移到废纸篓与恢复；提供明确的目标冲突/撤销语义。
4. **独立能力**：Terminal/脚本、网络读取、MCP。不是本批原生文件服务的隐式后门。

第 2–4 批未实现。Grep、Write、Edit 等是本项目的能力划分和名称，不宣称是已核实的 Raycast 私有工具清单。已有应用、日历、计算器等模块工具继续由模块拥有。

## 公共架构与许可边界

`AIFileToolProvider → AIToolRun → prepare → 本机确认 → execute(Prepared)`

- AI Chat 与 Quick AI 共用会话、声明、执行、过程与确认 UI；提供商只转译公共工具协议。
- 目录登记和 Search Tools 只读声明，不扫描目录、不解书签、不执行处理器。实际文件调用先在 Core actor 准备目标，再请求许可。准备只开句柄、核对路径和元数据，不读正文或枚举目录名。
- Prepared 持有本次**匹配**根目录、父目录链和既有目标的句柄，绑定同一授权 lease；不是先确认一串原始路径、随后重新按路径找到另一个对象。目标改名、替换、内容修改或作用根变化时失败，Prepared 不能重放或换成另一份未撤销的 lease。
- 文件工具默认关闭，仍需要原有全局工具开关。名称、根句柄列表、目录列表、元数据、Glob 和 Grep 结果与正文都属于披露，**全部逐次确认**，不以“不是正文”为由绕过。
- 本机确认显示匹配的根、规范化目标、模型和实际**直接接收方**；路径等值用 JSON 转义，避免文件名中的换行冒充确认字段。API 显示经现有连接校验的实际请求 URL，包括自定义代理及 Ollama 地址，不根据品牌名称猜测本地/云端。CLI 显示所用本机进程，并明确其后续网络接收方由 CLI 配置决定、Keylane 无法核实，不能声称完全本地或一定发往官方服务器。没有接收方信息时拒绝披露。
- 目录绝对路径仅保留在本机确认中，不写入过程历史、工具结果或声明。模型使用 `root_1` 等根句柄及相对路径；根列表也不返回本机目录名。文件正文自身可能包含路径或其他个人信息，因此仍须逐次确认正文披露；此策略不冒充任意秘密内容扫描器。
- 确认前的准备失败与用户拒绝使用相同的模型侧结果，统一返回未获核实与披露许可，不向模型区分文件不存在、目标已存在、受保护路径或根配置失效，避免错误信息形成存在性旁路。
- 同一个规范化路径策略用于根、直接 Read/File Info、目录行、Glob 和 Grep：常见凭据路径不开放，也不通过元数据或递归结果泄露。敏感目录不进入递归，目录中敏感名称不返回；符号链接、设备、管道和多硬链接普通文件不披露。结果中的每个对象都保留句柄，并在返回前复核路径、身份和版本。
- 旧 `keylane_search_files` 索引处理器原先直接返回绝对路径，没有共用本许可流程，因此本版暂不登记。Launcher 本身的文件搜索仍保留；后续索引工具必须接入同一许可边界，不能作为旁路。

## 当前工具契约

| 名称 | 行为 | 许可 |
| --- | --- | --- |
| `keylane_search_tools` | 只检索本次声明，无本机文件数据 | 无文件访问 |
| `keylane_file_roots` | 返回根句柄与默认根，不返回目录名或绝对路径 | 逐次确认 |
| `keylane_read_file` | 普通 UTF-8 分段读取，或目录非递归分页 | 逐次确认；保护路径拒绝 |
| `keylane_file_info` | 类型、大小、修改时间、revision | 同一披露策略，不豁免元数据 |
| `keylane_glob` | 相对路径 `*`、`?`、`**` 匹配 | 同一披露策略，过滤保护路径 |
| `keylane_grep` | 忽略大小写的字面匹配及短摘录 | 同一披露策略，过滤保护路径 |
| `keylane_write_file` | 只在匹配授权根内创建一级 UTF-8 文件 | 逐次确认；目标必须不存在 |
| `keylane_create_directory` | 只在匹配授权根内创建一级目录 | 逐次确认；目标必须不存在 |

`keylane_edit_file` 不登记，旧调用也拒绝；Write 的 replace/expected_revision 参数不再提供，Core 同样拒绝 replace。系统没有通用的“仅当目标仍是某 inode/revision 才原子覆盖”的文件接口，因此本版不把先 stat 后 rename 包装成条件覆盖保证。

## 创建与撤权的提交边界

- 创建仅允许一级名称，父目录就是已核实的授权根句柄。可改名移出的普通子目录不能直接作为写入父目录；若需要往子目录创建，用户必须先单独授权该目录。这也避免把当前仍在范围内的路径检查误当作可永久授予任意后代目录的能力。
- 新文件在应用临时区创建、立即解除目录链接，暂存内容只由未继承给 CLI 的文件句柄持有。最终使用 `fclonefileat` 从该句柄向授权根发布，目标存在即失败，不按暂存文件名重新打开，也没有非条件 rename/覆盖回退。
- 当前文件系统或跨卷克隆不支持上述操作时失败关闭。因此此版本文件创建主要适用于支持 FD 克隆的同卷 APFS；不宣称所有外部卷或网络文件系统都可创建。
- 授权撤销和最终发布共用锁，取消也有独立的同类 gate。撤权/取消先完成则不能进入提交；如果提交已经取得 gate，撤权会等本次小提交退出后才返回。保证的是该线性化边界，不是撤权能回滚此前已完成的文件创建。
- 全部读取、递归和提交 IO 在 Core actor 执行；授权根、父链与目标在准备、执行及结果返回时复核，不在主线程扫描。外部进程不受本进程的锁控制；检查不能冻结文件系统路径。本实现固定已确认的对象句柄，拒绝可检测的变化，不声称能阻止外部进程在之后改名、删除或替换它自己可写的对象。

## 限额

目录单次最多 100 条、最多枚举 10,000 个名称；Read 单次最多 4,096 字节并返回 next_offset。目录变更后分页不保证稳定。Glob/Grep 最深 12 层、最多 100 项，最多扫描 10,000 个名称；Grep 单文件 1 MiB、累计 8 MiB，结果超限标记 truncated。内部访问计数不作为文件元数据返回。

工具参数沿用 16 KiB、单项输出 32 KiB、单次运行最多 12 次调用及 128 KiB 输出的公共预算。创建文本另限 12,000 UTF-8 字节。没有任意 shell、二进制解析、递归删除、隐式 Full Disk Access 或系统权限申请。
