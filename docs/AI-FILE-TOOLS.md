# AI 基础文件工具

## 调查边界与实现顺序

调查日期：2026-11-20。只参考公开手册与用户提供的界面截图，不使用 Raycast 私有实现。公开手册没有列出所有内部文件工具的完整名称和参数，因此不能把下面的 Keylane 工具名当作 Raycast 的官方接口清单。

| 证据 | 可以确认的能力 | 对 Keylane 的含义 |
| --- | --- | --- |
| [Raycast Projects](https://manual.raycast.com/ai/projects) | 项目工作目录支持读取、修改文件；本地目录不会自动上传整个项目 | 项目目录作为本次会话默认根目录，实际读取结果才进入模型上下文 |
| [File Search](https://manual.raycast.com/file-search) | 文件搜索范围、忽略规则和内容设置；AI 使用文件搜索与 Finder 能力 | 索引搜索与按路径读文件分开，已知路径不能依赖索引命中 |
| [AI Extensions](https://manual.raycast.com/ai/ai-extensions) | 工具可来自内置能力、扩展与 MCP，执行受权限控制 | 基础文件能力由宿主提供，业务工具仍由对应模块登记，共用执行与确认层 |
| [AI Chat](https://manual.raycast.com/ai/ai-chat) | 附件、工具和大结果处理 | 用户主动附加文件与模型主动读文件是两个入口，不能混同授权 |
| [开发者工具 API](https://developers.raycast.com/api-reference/tool) | 扩展可以声明工具及参数 | 统一声明契约，不在聊天窗口或提供商适配器里实现文件操作 |
| 用户提供的下载目录执行截图 | `Search Indexed Files`、`Search Tools`、`Glob`、`Read`；`Read` 参数为目录路径 | 这些名称与目录读取行为有直接界面证据；截图没有证明其他内部工具的精确参数 |

按依赖分批：

1. **本批已实现**：工具元数据发现、授权根目录、目录/文本读取、元数据、Glob、文字搜索、新建/替换文本、精确编辑、创建目录。
2. **后续**：PDF/其他文档提取、大结果文件与更好的分页、文件搜索索引工具与基础工具的检索协同。
3. **后续单独评审**：复制、移动、重命名、移到废纸篓与恢复；提供明确的目标冲突/撤销语义。
4. **独立能力**：Terminal/脚本、网络读取、MCP。不是本批原生文件服务的隐式后门。

第 2–4 批未实现。Grep、Write、Edit 等是本项目的能力划分和名称，不宣称是已核实的 Raycast 私有工具清单。已有应用、日历、计算器等模块工具继续由模块拥有。

## 公共架构

`AIFileToolProvider → AIToolRegistration → AIToolRun → AIFileToolService`

- AI Chat 与 Quick AI 通过同一个 `AIConversationSession` 获取宿主和模块工具。附件菜单、工具过程与确认卡继续使用现有公共组件。
- 提供商适配器只转译相同的工具声明和结果：OpenAI 兼容 API（含 Ollama、自定义提供商）、Anthropic、Codex 订阅、Claude 订阅均复用本执行层。模型自身不支持工具时仍按原策略拒绝工具模式。
- 工具目录只读取配置与声明，不能列目录、解书签、启动索引或运行处理器。`Search Tools` 仅检索本次已声明元数据；目前并非动态加载更多隐藏工具。
- 所有文件 IO 在 Core actor 中执行，原生文件描述符操作，无 shell、无主线程递归扫描。
- 文件工具有独立默认关闭的开关；启用还需打开原有全局工具开关。目录由设置中的原生选择面板显式添加，或来自当前项目已经选择的工作目录。没有自动授权整个用户目录或下载目录。
- 文件授权变更使旧 lease 失效，重新启用不能恢复旧调用。切换项目停止当前请求；修改当前项目也停止请求，旧目录不能继续写入。

## 本批工具契约

| 名称 | 行为 | 确认 |
| --- | --- | --- |
| `keylane_search_tools` | 检索当前声明的名称、说明、参数 | 无执行效果 |
| `keylane_file_roots` | 返回已配置路径及默认根目录，不扫描 | 无正文访问 |
| `keylane_read_file` | 文件按 UTF-8 字节分段读取；目录按名称排序、非递归分页 | 普通文件在授权范围内直接读；已识别敏感路径逐次确认 |
| `keylane_file_info` | 类型、大小、修改时间、revision | 不读正文 |
| `keylane_glob` | 相对目录的 `*`、`?`、`**` 路径匹配 | 不读正文 |
| `keylane_grep` | 忽略大小写的字面文字匹配，返回路径、行号和短摘录 | 跳过敏感路径、隐藏项与过大/二进制文件 |
| `keylane_write_file` | 默认新建且禁止覆盖；replace 要求最新 revision | 每次确认 |
| `keylane_edit_file` | 精确文本替换，默认拒绝多处匹配；明确 replace_all 才全部替换 | 每次确认，要求最新 revision |
| `keylane_create_directory` | 在已存在的授权父目录内创建一级目录 | 每次确认 |

目录仅表示操作范围，不表示整个目录的内容已发送。读取所得文字会交给本次所选模型；设置中明确说明该行为。敏感路径识别覆盖常见凭据/密钥目录与文件，但不是能够识别任意文件内容的秘密扫描器。用户应只授权所需目录。

## 边界与限额

- 先规范化路径并检查目录边界，再从根目录逐段 `openat(O_NOFOLLOW)`；不跟随用户目录中的符号链接。macOS 的 `/var`、`/tmp`、`/etc` 系统别名单独规范化，避免 Foundation 简写造成误拒绝。
- 只解析并启用当前操作所需的书签。失效、移位或损坏书签拒绝访问，无交互恢复、无权限弹窗；不影响其他授权目录。
- 目录单次最多 100 条、最多枚举 10,000 个名称；文件 Read 单次最多 4,096 字节，返回 `next_offset`；分页只保证在目录未发生变化时稳定。
- Glob/Grep 最深 12 层、最多 100 个结果，扫描最多 10,000 个名称；Grep 单文件最多 1 MiB、累计正文最多 8 MiB。结果超限明确标记 truncated。
- 单次工具输出最多 32 KiB，单次运行最多 12 次调用及 128 KiB 输出。大任务须缩小范围，不隐式扩大预算。
- 写入先暂存并同步，再检查 revision，最后原子替换；新建采用 exclusive rename，不覆盖已有文件。文件变化需重新读取，取消时清理本操作的临时文件。替换硬链接路径不会原地修改其他链接。
- revision 基于 inode、大小、纳秒修改/变更时间等元数据，不是跨进程事务锁；不能保证抵御不合作进程在最终检查与 rename 之间的所有竞争。取消/撤权发生在实际提交之后也不能自动撤销已完成写入。
- 本批仅 UTF-8 普通文本，不读二进制、设备、管道，不执行文件，不递归删除，不提供 shell，不直接授予 Full Disk Access。

## 验证

- `Tests/KeylaneCoreTests/AIFileToolsTests.swift`：实际临时文件，覆盖排序分页、UTF-8 边界、大文件限额、Glob/Grep、越界及符号链接、过期 revision、覆盖冲突、精确编辑、目录创建、硬链接、撤权、暂存取消清理。
- `bash scripts/verify-ai-file-tools.sh`：实际公共注册/执行/确认层，覆盖默认关闭与持久化、普通/敏感读取、拒绝/允许写入、确认期间移除再授权、关闭再开启、项目切换、目录损坏隔离、Search Tools 不执行处理器。
- `bash scripts/verify-file-ai.sh`：公共会话与提供商传输回归，使用合成 HTTP/CLI 工具调用数据。

这些测试不读取真实下载目录，不访问用户账户或模型服务，不代表已完成真实提供商的端到端调用或安装版交互验收。实际使用需在设置启用工具并显式选择目录。
