# 文件元数据与正文提取分离（FILE-01，第二批）

基于 dev `41dcc4cd`，承接尚未合并的 PR #243。第二批通过单独工作树和增量 PR 交付；本批不修改设置布局、权限入口或正文检索开关的含义。

## 调度与持久化

- 扫描事务只提交名称、目录/符号链接/卷/修改时间等元数据，并为支持的普通文件登记正文待办。慢 PDF、文本读取不在索引事务或元数据写入队列中执行。
- 待办保存在新增的 `file_content_queue` 表中。请求 token 与文件元数据一并提交；扫描代次与正文待办状态分离，不改动旧数据库记录、全文表或设置键。旧版本已经提取的正文继续复用，升级不强制重新提取全部文件。
- 一个 utility 队列串行提取，每批最多 8 个文件；读取和解析逐文件释放临时对象，最多保留 8 个各不超过 100000 字符的结果。每批共用一个回写事务，批次间短暂让出执行。队列为空时没有轮询定时器；读取失败保留待办，60 秒后再试，数据库提交错误也会退避，不形成快速重试循环。
- 正文回写核对请求 token、路径归属、修改时间和记录类型。旧请求不能覆盖新元数据，暂停/禁用/授权或筛选变化会撤销提取代次；写入事务内再次检查取消并回滚。删除记录自动删除对应待办，关闭正文检索原子清除正文与待办。
- 暂停、关闭和重启保留未完成请求。即使原生 PDF 调用还在返回，也保留原工作槽，避免反复启停创建多个提取线程。文件系统调用和 PDFKit 单页原生调用不能硬中断；在文件、读取块和页边界检查取消，不宣称已实现独立进程隔离。
- 从已打开的文件描述符读取，小批次内最多复用 8 个固定搜索根句柄，路径替换会拒绝继续使用、批次结束后释放；逐级拒绝用户符号链接，检查修改时间、inode、大小与读取前后版本；不读取 dataless 或 iCloud 管理的正文，不主动请求占位文件下载。保持 2 MiB 输入、100000 字符输出和原有文本类型限制，PDF 按页提取至字符上限。
- 设置宿主复用原加载指示器，同时观察元数据和正文状态。正文未完成时，正文搜索显示后台补充提示；结果刷新合并到约 300 毫秒一次。

## 性能与交付边界

同一组隔离的 200 个文件（96 文本、24 个双页 PDF、80 二进制）交替对照五轮：旧路径在元数据事务中读取正文；新路径先提交元数据，再完成正文。创建文件不计入时间，支持类型、原生正文读取及数据库写入均计入总 CPU。元数据可用耗时和总提取 CPU 分开报告，不能把延后执行当成省掉工作。

早期未优化测试构建的逐文件回写出现约 15% 总 CPU 增幅，随后改为最多 8 个结果共用事务，并在批次内固定搜索根、复用最多 5 个队列写入 SQL 计划（每次清空正文参数）。不能将测试构建耗时当成 Release 安装版表现。

最终 `KEYLANE_FILE_TEST_RELEASE=1 KEYLANE_FILE_TEST_SOURCE=Tests/Integration/file-content-benchmark.swift bash scripts/verify-files.sh` 使用 `-O`，同组 200 文件交替五轮结果如下：

| 指标 | 旧同步路径 | 新拆分路径 |
| --- | --- | --- |
| 元数据提交 wall time，中位数 | 331.6 ms | 6.96 ms |
| 总提取 CPU，中位数 | 0.3298 s | 0.3443 s |
| 总提取 CPU，五轮范围 | 0.3283–0.3541 s | 0.3419–0.3447 s |

元数据提交约减少 98%；完整提取总 CPU 中位数增加约 4.4%，每 200 个文件约增加 0.0145 CPU 秒，属于持久化排队和安全版本校验的额外成本。本批改善响应与恢复能力，尚未证明整体能耗下降。三轮早期样本曾表现为略降，最终以五轮结果为准。此 Core 对照不包含控制器批次间让出和 UI 刷新，不能用其 total wall time 推断用户等待全部正文补齐更快。原生提取流程与旧同步逻辑均使用同一组实际临时文件，无人工延时；阻塞提取只用于另一个行为测试。

### 2026-11-25：重叠范围与持久任务防护（PR #245，待合并）

- 路径的索引归属切换时，同一事务换发正文待办代次、清除旧范围凭据及重试延时。即使归属随后切回，旧待办也不能提交、删除或延迟当前待办。
- 正文待办由当前授权范围的扫描器登记目录和文件版本；仅有旧路径、没有可验证版本的待办不会读取正文，等扫描器重新确认。读取前后核对实际目录、原文件版本和当前范围规则。失联、撤销或无法核实授权时保留名称索引，不使用其他重叠范围的访问权限。已知的 iCloud／文件提供商路径、占位或过大文件不提取正文；如果无法取得已知本地常规文件的元数据，也拒绝读取。失效证据等待重新扫描；暂时 I/O 错误最多再定时尝试一次，之后等重新扫描。书签存在但过期、无法解析或不能启动匹配范围时，不用进程的普通权限回退。
- 验证范围：合成 SQLite 与文件搜索控制器用例；本轮没有安装、签名或访问个人索引，暂不报告新的性能或外置卷／iCloud 实机结果。
