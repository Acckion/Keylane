# 文件元数据与正文提取分离（FILE-01，第二批）

基于 dev `41dcc4cd`，承接尚未合并的 PR #243。第二批通过单独工作树和增量 PR 交付；本批不修改设置布局、权限入口或正文检索开关的含义。

## 调度与持久化

- 扫描事务只提交名称、目录/符号链接/卷/修改时间等元数据，并为支持的普通文件登记正文待办。慢 PDF、文本读取不在索引事务或元数据写入队列中执行。
- 待办保存在新增的 `file_content_queue` 表中。请求 token 与文件元数据一并提交；扫描代次与正文待办状态分离，不改动旧数据库记录、全文表或设置键。旧版本已经提取的正文继续复用，升级不强制重新提取全部文件。
- 一个 utility 队列串行提取，每批最多 8 个文件；读取和解析逐文件释放临时对象，最多保留 8 个各不超过 100000 字符的结果。每批共用一个回写事务，批次间短暂让出执行。队列为空时没有轮询定时器；读取失败保留待办，60 秒后再试。
- 正文回写核对请求 token、路径归属、修改时间和记录类型。旧请求不能覆盖新元数据，暂停/禁用/授权或筛选变化会撤销提取代次；写入事务内再次检查取消并回滚。删除记录自动删除对应待办，关闭正文检索原子清除正文与待办。
- 暂停、关闭和重启保留未完成请求。即使原生 PDF 调用还在返回，也保留原工作槽，避免反复启停创建多个提取线程。PDFKit 单页原生调用不能硬中断；在文件、读取块和页边界检查取消，不宣称已实现独立进程隔离。
- 从已打开的文件描述符读取，逐级拒绝用户符号链接，检查修改时间、inode、大小与读取前后版本；不读取 dataless 或 iCloud 管理的正文，不触发占位文件下载。保持 2 MiB 输入、100000 字符输出和原有文本类型限制，PDF 按页提取至字符上限。
- 设置宿主复用原加载指示器，同时观察元数据和正文状态。正文未完成时，正文搜索显示后台补充提示；结果刷新合并到约 300 毫秒一次。

## 验证

- 455 项 Swift 测试、30 项发布保障测试和版本检查通过。
- 新增阻塞提取器集成：提取阻塞时元数据已可搜索，独立数据库写事务可完成；新元数据覆盖旧请求、暂停/停止阻止迟到写入、重启续做和关闭正文清理通过。阻塞提取属于注入验证；真实文本与 PDF 由原有文件集成另行验证。
- 原有文件集成通过，覆盖中文、多关键词、仅文件名/正文混合、UTF-8、PDF、体积和字符上限、暂停恢复、忽略规则、授权、动态事件和离线保留。第一批重启与局部失败保护在最终代码上另行复验。
- Core 测试覆盖队列持久化、扫描不误删待办元数据、旧 token 拒绝、新请求保留、提交中取消回滚、退避、删除与关闭清理，以及实际描述符读取与符号链接拒绝。
- 无密钥 CI 覆盖所有 PR 目标，包括依赖尚未合并功能分支的增量 PR；dev/main push 的签名边界不变。新正文集成加入既有 Checks，不跳过第一批检查。

## 性能与交付边界

同一组隔离的 200 个文件（96 文本、24 个双页 PDF、80 二进制）交替对照三轮：旧路径在元数据事务中读取正文；新路径先提交元数据，再完成正文。创建文件不计入时间，支持类型、原生正文读取及数据库写入均计入总 CPU。元数据可用耗时和总提取 CPU 分开报告，不能把延后执行当成省掉工作。

初版逐文件回写出现约 15% 的总 CPU 增幅，已改为最多 8 个结果共用事务，后续独立复验及安装结果补录。本批不宣称达到长期能耗或按 60% 后台/40% 前台平均低于 100 MB 的目标。忽略规则访问的文件系统等待、查询调度和缓存预算仍是后续工作。
