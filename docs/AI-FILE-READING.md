# AI-13-a：PDF、结果续读与索引衔接

本批见 [PR #224](https://github.com/Acckion/Keylane/pull/224)，从 dev `1eea4a6` 建立独立分支，现已集成 dev `2ad472e` 及尚未合并的 PR #215 `c87e260`。实现与验证仅在本批分支，不代表 dev 或安装版已有这些能力。

## 用户可见行为

- 公共 Read 支持 UTF-8 文本、有文字的 PDF 和目录。PDF 可指定 `page` 从某页开始；正文每次最多 4096 UTF-8 字节，目录每页最多 100 条。扫描件、加密 PDF、Office 文档和 OCR 没有接入。
- 返回 `cursor` 时用 `keylane_read_result` 继续，仍逐次确认目标与接收方。正文按完整 UTF-8 边界续读；PDF 的 offset 是提取文字的字节位置，不是 PDF 二进制位置。不要同时指定 page 和 offset。
- 目录、Glob、Grep 和索引结果使用当前请求内的快照，新增文件不会挤入旧分页。每页返回前重新核实对应条目的身份与 revision；相关文件替换、改名或内容变化时拒绝该页，需要重新查询。
- 安全索引入口为 `keylane_search_indexed_files`。它只查询已存在的文件名索引，不启动扫描、不修改页面查询或选中状态，不读取索引正文。文件搜索配置范围与 AI 已授权范围取交集：先在 SQL 中限定子树，再以已确认的根句柄检查结果，不把过时索引当作读取许可。
- 索引结果仍使用根句柄和相对路径，正文统一走公共 Read；没有再增加一套文件读取循环。关闭文件搜索、改变授权/规则、切换项目/模型或停止请求后，旧引用不能继续使用。

## 复用与生命周期

`AIFileDocumentText` 是附件和基础文件工具共用的 PDF 解析器。只接收调用方已从核实句柄读取的 Data，按页提取、检查取消和总文字额度，不按路径另开文件，不请求密码或 OCR。显式附件原有的文件/文字额度保持不变，不因为工具可以分页而自动发送更大的附件。

`AIFileToolService.ReadSession` 属于本次工具注册批次，使用 AIToolRun 自己生成的请求 ID 绑定。即使误复用同一组注册对象，也不能跨请求/模型连接重用游标。游标在结果验证、编码成功后一次性替换；拒绝该页或页大小/UTF-8 边界等可恢复错误不消费游标，可以调整参数重试。已成功披露的页不能重放；达到缓存上限时仍允许原位替换当前游标。

- 文本续读保留原文件句柄与版本，只读取下一片段，不预先读取整份大文本。
- PDF 提取文字及多页列表保存在应用私有、创建后立即解除目录链接的临时文件中；模型只拿到不透明游标。没有可供 CLI 打开的临时路径，不把临时文件路径写进历史，不在重启后恢复。
- 快照内容由本机保存，每次披露仍走 #215 的 prepare/确认/执行边界。缓存不是对原权限的替代：原根、父链、目标及该页条目仍须核实。
- Prepared 的来源有效性加入公共运行层检查，所有提供商在后续工具执行/模型往返前重查，不能在索引配置撤销后继续发送缓存页。

## 额度与失败边界

| 项目 | 上限/语义 |
| --- | --- |
| PDF 原文件 | 8 MiB、100 页；不解锁、不 OCR |
| 单份私有结果 | 2 MiB，包含分页所需标记/元数据 |
| 每请求缓存 | 最多 32 个活跃游标、合计 8 MiB、64 个保留句柄预算 |
| 相对路径父链 | 最多 32 层；更深目录需单独选择为授权根 |
| 文本输出页 | 最多 4096 UTF-8 字节 |
| 列表输出页 | 最多 100 条及约 24 KiB 行数据，保留公共 32 KiB 单项输出限制 |
| 目录快照 | 最多枚举 10,000 个名称，快照约 2 MiB；不足时明确截断 |
| Glob/Grep | 最多 10,000 名称、1000 匹配；Grep 原有 1 MiB 单文件/8 MiB 累计正文预算保留 |
| 索引候选 | 最多 200 条；达到候选上限则保守标记 source_truncated |
| 整次运行 | 原有 6 轮/12 次工具/128 KiB 输出预算不放宽 |

`truncated` 表示仍有缓存页或源扫描未完成；`source_truncated` 明确标记源候选/扫描上限。没有下一游标但 source_truncated 为 true 时，必须缩小查询范围，不能声称已列出全部文件。

系统标记为 SF_DATALESS 的占位文件在打开/读取前拒绝，不主动请求下载。此检查不替代真实文件提供商验收；本批没有使用真实 iCloud 或其他云端文件测试。PDFKit 本身的解析依赖系统实现，这些额度也不等于对解析器内存/耗时的进程级硬隔离。

覆盖、编辑、移动、复制、废纸篓、网络读取、Terminal 和 MCP 均不因本批而开放。创建仍保留 #215 的根内一级、不覆盖和受支持文件系统限制。
