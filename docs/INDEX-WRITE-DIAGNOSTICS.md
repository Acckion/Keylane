# 索引写入诊断与无效更新去重（第一批）

承接 PR #247 的已提交基线 7927463；独立分支 `fix/index-write-diagnostics`，待合并。当前阶段不拆表、不更改事件恢复、权限或正文重试策略。

## 行为

- `touchUnchanged` 先查紧凑元数据：同代次、同归属和卷信息直接返回命中，不执行 UPDATE，不重新入正文队列。新代次仍需写标记以保留删除对账语义；这一批不能消除无变化整轮扫描的全部写入。
- `put` 的冲突更新仅在字段不同才执行。FTS 更新触发器增加新旧名称/正文比较，避免纯元数据或相同正文重建全文索引。
- 老数据库首次打开时事务性替换旧触发器，后续打开不重复修改 schema。保留记录、全文索引与数据库版本兼容性，不清库。
- 正文完成仅在正文不同且原有路径/归属/版本/任务 token 全部有效时更新；相同结果仍删除对应已完成任务；过期任务不能影响新任务。回滚恢复诊断计数。

## 诊断

统一日志 subsystem `org.keylane.launcher`、category `file-index-diagnostics`。每次扫描只记开始与结束：全量/增量、请求来源（通用请求/文件事件/事件恢复/恢复点不完整）、强制标记、目标数量、耗时、取消和成功状态；结束携带当前数据库实例的累计元数据检查/写入/跳过、正文写入/跳过或过期、延后与成功事务数。

不记录路径、文件名、查询、正文或权限内容。只有固定数量整型计数，无逐文件日志、计数历史数组或额外定时器。累计计数可能包含同时进行的正文和实时补丁，不当作单轮扫描独占成本；进程读写字节仍需外部采样关联。通用 request 尚不能区分所有设置/手动调用，失败类型细分留在正文重试批次。

## 验证与边界

新增回归覆盖同代次无写入、相同空正文完成任务、新代次删除对账、回滚恢复计数、旧触发器升级和相同字段 UPDATE 不触碰 FTS shadow tables。沿用原有非空正文/旧任务 token/修改时间变化/重试/取消测试；真实临时文件集成复验正文生命周期及阻塞基线期间动态文件变化。

仅修改时间变化但正文相同，目前仍走旧版清正文再提取路径，不在本批宣称解决；它需要后续正文版本与结果复用设计，不能以返回旧正文破坏搜索正确性。实际安装、长期磁盘读写和 12 小时能耗尚未验收，平均内存小于 100 MB 的目标仍未达。

本轮本机验证：471 项 Core 测试通过，其中索引专项 21 项；正文生命周期 5 项、真实 FSEvents 动态更新 5 项均通过。最初受限环境下的完整测试有原生文件操作权限失败，已在正常本机环境完整重跑通过，未跳过或削弱断言。云端 Checks 与安装版验收尚未完成。
