# 0.9.1 搜索响应与主界面文件搜索

## 设置入口

设置 → 文件搜索 → “在主界面搜索文件”。默认关闭；开启后在主搜索中合并应用、命令和最多10条文件结果，仍可进入文件搜索页面查看最多200项。关闭时主界面不启动文件查询。开关持久化，旧0.9.0配置缺少此字段时默认关闭，不丢失原范围或其他设置；切换开关不重建索引。

## 闪烁和延迟修复

旧实现每约500项索引进度都调用search，先发布空列表，再重新查询和排序。旧的输入请求也会在读取队列累积，忽略规则每条结果重复解析，排序重复处理同一名称。

- 输入查询合并60ms；旧排队任务跳过，正在执行的SQLite查询通过progress handler取消。
- 保留当前结果直到新查询快照准备完毕，查询切换期间禁止执行旧文件动作。
- 索引进度最多每秒更新；只有尚无结果时才进行中途补查，有结果后在本轮索引结束时合并一次。
- 相同结果和状态不重复发布；相同关键词刷新保留既有顺序，新项追加，选中项尽量按稳定ID保留。
- 索引统计不再转发到启动器整体重绘。隐藏目录和未纳入范围的Library变动不触发全量重扫。
- 忽略规则编译缓存，并在每次查询预先准备；候选排序分数只计算一次，不进行与文件索引匹配无关的拼音转换。
- 读连接在索引遍历前初始化，避免初始化DDL与大目录写入争用。

## 验证

28项核心测试通过。新增旧设置解码与SQL中途取消后继续查询测试。

文件集成测试通过：同一关键词反复查询/重建不出现空快照、不重复回调；快速切换关键词不会发布旧结果；主界面开关持久化且不重建；中文、多关键词、忽略规则、正文、文件事件和离线策略回归通过。这是数据和控制器层验收，安装版物理操作和视觉仍待用户复验。

对比基线afaff98，使用相同优化编译、15000条生成文件记录、最多2000个候选、同机交替两字中文查询：

| 查询层耗时 | 0.9.0 | 0.9.1 |
|---|---:|---:|
| 首次 | 599.23ms | 38.90ms |
| 热查询P50 | 444.28ms | 38.42ms |
| 热查询P95（10次） | 493.35ms | 40.00ms |

这是合成索引的查询层测量，包含查询、过滤和排序；不含60ms输入合并、实际窗口绘制、真实用户目录或网络磁盘延迟，不等同于全场景响应承诺。
